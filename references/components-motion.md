# 组件实现与动效契约

本章聚焦桌面 Agent 应用的核心组件工程实现与交互动效物理规范，涵盖自适应输入框、流式消息跟随、工具卡片状态机与性能优化。

---

## 1. 智能输入框（Composer）工程实现

输入框是桌面 Agent 的操作起点。必须先明确草稿、附件上下文、发送、排队与中止的状态归属，再处理视觉过渡。

### 自适应高度与滚动上限

1. 优先复用现有组件库的自动增高输入框。目标引擎支持时可使用 `field-sizing: content`，同时设置最小高度、最大高度和溢出滚动；见 [S6](sources.md)。
2. 不支持时复用已有的自动尺寸模块，或在输入变化时按 `scrollHeight` 更新高度。`ResizeObserver`（尺寸观察器）适合监听容器宽度等外部变化；单独观察一个固定高度的文本域不会使它随内容自动增高。
3. 高度过渡是可选效果；检查连续输入、粘贴、选区和光标可见性，并响应减弱动态效果。外层是否裁切取决于结构，不能无条件要求 `overflow: visible`。
4. 滚动条默认保留平台或现有组件的行为。只有产品明确需要时才局部隐藏，并验证滚动提示、鼠标拖动、键盘、触控板和高对比度模式；保留滚轮事件不等于完整保留可访问性。

### 输入法安全发送

- 优先沿用现有组件的组合输入处理，或采用 [事件基线示例](open-claude-manual.md#2-输入法安全发送事件基线与兼容边界)。
- 不使用固定的 500 毫秒窗口推断“伴生键”；平台兼容分支先提供真实事件序列和对应回归。
- 覆盖组字确认、空格或点击选词后立即发送、连续回车、多输入框隔离与产品配置的换行快捷键。
- 附件解析、传输成功、失败和移出上下文要对应真实状态。

## 2. 流式消息输出与用户视口跟随策略

在桌面大屏上，模型流式吐字速度极快，如果简单地使用 `element.scrollIntoView()` 暴力滚动，会导致试图向上翻看历史记录的用户被强制拉回底部，引发极度挫败感。

### 视口智能跟随算法
1. **自动跟随状态判定**：
   - 在追加内容或高度改变之前，记录用户是否希望继续跟随，再结合底部距离判断：`distanceFromBottom = scrollHeight - scrollTop - clientHeight`；
   - 设定容差阈值（如 `threshold = 40px`）：
     - 当 `distanceFromBottom <= threshold` 时，认为用户处于“底部跟读模式”，新流式文字或工具卡片追加时保持贴底；避免每个片段都重启动平滑滚动；
     - 用户主动向上回溯时暂停跟随。不要仅在追加内容后根据距离判定用户离底，否则内容变高本身会误关跟随；
2. **“回到底部”悬浮按钮**：
   - 当用户处于回溯阅读模式且下方有新消息生成时，在右下角悬浮轻量按钮（如“有新回复 ↓”），点击后平滑滚动回底部并重新激活跟随；
3. **内容高度突变防抖**：
   - 代码块高亮、图片加载、折叠展开时先检查浏览器滚动锚定与列表库的补偿行为；确需手动恢复时锚定可见内容的位置，避免把全部高度变化都累加到 `scrollTop` 而产生双重补偿。

## 3. 工具、审批与产物组件规范

| 组件类型 | 核心状态职责 | 严防错误 |
| --- | --- | --- |
| **Tool Execution** | 调用标识 ID、输入参数、执行中进度、成功结果或错误原因 | 每个事件零散打出一张卡；将接口已受理直接误标为已执行完成 |
| **User Approval** | 拟执行操作、影响范围、目标文件列表、允许/拒绝动作 | 只问“是否同意”，不展示具体受影响的文件路径或命令 |
| **Plan / Roadmap** | 总体步骤清单、当前进行中步骤、已完成步骤 | 将模型文本里的 `- [ ]` 错当成系统执行证据 |
| **Artifact / Diff** | 代码/文档差异、单向合并、整文件预览、一键导出 | 预览成功直接误判为本地文件已写入落地 |

## 4. 可拖拽分栏与多面板工作台

在对话与产物并排展示的双栏或多栏布局中：
- 分栏宽度拖拽手柄必须具有清晰的 hover 与 active 视觉反馈；
- **可选吸附与取消恢复**：先沿用分栏库；阈值依据内容最小宽度与窗口尺寸确定。若支持取消，恢复拖拽前的比例及折叠状态，释放指针捕获并清理监听，不强制展开某一侧；
- 左右面板必须拥有完全独立的滚动容器，严禁产生跨面板的全局水平滚动条。

## 5. 动效设计物理学与空间关系

交互动效应当为用户传递界面状态与空间因果关系，拒绝为了修饰而无故添加冗余动画：

1. **动效目的优先**：
   - 确认用户动作（点击即时响应反馈）；
   - 提示状态迁移（从草稿态收缩进入运行态）；
   - 表达空间来源（侧边栏抽屉从物理边缘划入）；
   - 维持对象连续性（小卡片平滑展开为大工作区）。
2. **阻尼与弹性标准**：
   - 浮层展开与微交互偏好轻微有阻尼的 Spring 物理曲线；
   - 避免过度过冲（Overshoot）导致界面晃动与视觉眩晕；
   - 必须支持用户中断与快速连续击键，动画执行期间不能阻塞正常交互；
3. **系统级无障碍适配**：
   - 监听媒体查询 `@media (prefers-reduced-motion: reduce)`；
   - 当用户系统开启减弱动态效果时，瞬时切换状态或使用极简透明度渐变，严禁出现大幅位移与缩放。

## 6. 视觉几何学、边框与字号规范（Visual Geometry, Borders & Typography）

桌面 Agent 界面对精致度与信息密度的要求极高，必须落实精确到半像素的几何物理学与字体约束：

### 同心圆圆角计算（Concentric Border Radius）
- **问题根因**：嵌套容器若内外两层使用相同的 `border-radius`，由于内外边距的挤压，内层四角会出现视觉变形，内外弧度无法保持同心平行，造成明显的粗糙感；
- **同心圆黄金公式**：
  $$R_{inner} = \max(0, R_{outer} - padding)$$
- **典型配方**：外层卡片 `border-radius: 12px`、内边距 `padding: 8px`，则内部嵌套项的圆角必须严格设为 `4px`；当 `padding >= R_{outer}` 时，内层元素应采用直角或至多 `2px` 微圆角。

### 光学对齐（Optical Alignment）
- 严禁单纯依赖 CSS 的几何包围盒（Bounding Box）进行机械贴边或居中；
- 对不对称图形（如播放三角形、返回箭头、外凸徽标）、大写英文字母与图标混合编排时，必须依据**视觉质心（Visual Center）**施加 1px 级别的光学补偿，确保肉眼感受平衡。

### 0.5px 精细微边框标准（Hairline Borders）
- 现代高分辨率（HiDPI / Retina）桌面显示器下，传统的 `1px` 边框在深色主题或多面板下显得厚重、粗笨并割裂视线；
- 界面上的分割线、卡片外边框、标签描边统一采用 **`0.5px`** 边框标准；
- **实现方式**：
  - 现代 Chromium / WebKit 直接支持 `border: 0.5px solid var(--border)`；
  - 或采用内嵌微阴影 `box-shadow: inset 0 0 0 0.5px var(--border)`，确保在各种缩放比率下保持极致纤细与现代感。

### 字体层级收敛法（Typography Hierarchy）
1. **全页字号阶梯严禁超过 4 种（推荐 3 种）**：
   - 推荐桌面标准阶梯：辅助微文本（`12px`）+ 正文/输入（`13px` 或 `14px`）+ 顶栏/模块标题（`16px`）；
2. **最小可用尺寸硬性门禁 12px**：
   - 严禁在界面任何位置使用小于 `12px`（如 10px、11px）的文字，杜绝在低 DPI 屏幕上字体渲染发虚模糊、损害可读性；
3. **多维表达主次关系**：
   - 严禁为了突出某行内容盲目创造第 5 种字号；
   - 必须优先通过**字重阶梯（400 常规 / 500 中粗 / 600 粗体）**、**字体灰阶/透明度对比（主色 / text-muted / text-subtle）**以及**空间外边距（Whitespace）**构建层级秩序。

### 圆角与阴影的克制使用
- 坚决杜绝无功能意义的装饰性圆角和扩散大阴影；
- 圆角与阴影必须严格服务于界面的物理层级（基底卡片低阴影或无阴影、浮层 Popover 中阴影、模态弹窗高阴影）；
- **严禁使用“卡片左边缘带颜色的粗线条”**这一过时的装饰性反模式，避免使页面碎片化并弄脏视觉。
